```text
Usage:
  python run_qwen3_benchmark.py --benchmark benchmark.json --mode both
  python run_qwen3_benchmark.py --benchmark benchmark.json --mode fp16
  python run_qwen3_benchmark.py --benchmark benchmark.json --mode 4bit

Files: result_fp16.json and result_4_bit.json (saved after every question).
```

## 四、Prompt：one-shot

優化後的題目在 [20_questions_improve.json](20_questions_improve.json)。本實驗以 **one-shot** 設計搭配明確指令，讓模型了解預期的回答形式與範圍。實際比對可知，優化版修改了全部 **12 題 knowledge 題**，4 題數學與 4 題程式題的輸入保持原文；兩版的標準答案也一致。

例如，生物分類題加入一個格式示例：

> 回答要求：請依照常見的傳統生物分類階層回答，先說明共有幾個層級，再按由大到小列出所有名稱，不需討論額外細分階層。格式示例（僅示範回答方式，並非本題答案）：分類共有 N 個層級：A、B、C。

MoE 題則加入回答順序與一個輸出格式示例：

> 回答要求：請依「核心原理→Experts與Router/Gating Network→依token計算分數並選Top-k→專家運算與加權合併→稀疏啟用的優點→負載均衡和通訊等缺點」的順序回答。格式示例（非本題答案）：原理：...；流程：1.... 2....；優點：...；缺點：...。

實際修改分成三類：

| 修改方式 | 題目與作用 |
|---|---|
| 單一格式示例 | knowledge_001、004、011、012 示範回答形式，減少格式與組織上的不確定性。 |
| 限定回答範圍 | 例如 NBA 題只回答常規時間、音樂題明確限定演出團體、遊戲題限定伺服器與活動。 |
| 提供參考網址與查證要求 | 法律、選舉、遊戲、音樂、MLB、NBA 冠軍題提供網址，部分題目要求不能查證時註明。 |

## 八、結論

本實驗完成開源 Qwen3-8B 部署，建立 20 題跨數學、知識與程式能力的 Benchmark，並以四組執行結果比較 Prompt 與模型精度。在數學、程式設計題在兩種精度下皆表現良好。法律、時事與特定領域題則是兩種精度共同的弱項，這大概是因為Qwen3-8B無法靠model自己連上網路去查詢資料。

採用格式示例與明確要求後，回答格式與長度有所改善，總生成 tokens 與總推論時間下降；但知識正確性沒有用，這只能去外接其他的AI agent讓Qwen3-8B去上網，但是這樣的方法是多此一舉，倒不如直接用別的LLM看看。
